# WithViewer — 静かな同席者

会議・動画の音声を記録し、その内容を共有したAIへ音声・テキストで相談するローカルWebアプリの検証版です。会議の音声入力と、利用者がAIに相談する入力を分けています。

## 起動

開発は`dev`ブランチを基本とします。`main`は本番用とし、今回の初回アップロードでは両方に同じ実装を反映します。以後、mainへの反映は明示的に行います。

Cloudflare Pagesで本人だけが利用する公開版の構成も追加しました。`npm run build:pages`でWorker付きの配信ファイルを作成します。Firebase AuthenticationのGoogleログイン・公開手順は[公開版の手順](docs/CLOUDFLARE_PAGES.md)を参照してください。画面にはログイン案内を表示し、APIはFirebase IDトークンと許可メールを検証します。

音声の文字起こしで一時的な通信・サーバーエラー（408/502/503/504）が起きた場合は、全区間の送信を待機し、30秒・120秒後に最大2回自動再試行します。復旧すれば残りの区間を順番に処理します。障害が続く場合、認証・利用枠（429）・Cloudflare実行上限の場合は自動送信を止め、録音音声は保存し続けます。「未完了区間を一括再試行」で保存済み音声を順次再送できます。個別の再試行も可能です。ページの再読込み後は自動再送せず、一括ボタンで開始してください。再送は追加のAPI利用となります。

Node.js 24.12以上とWindows版ChromeまたはEdgeを使用します。開発時の確認環境はNode.js 24.19.0、Chromeです。Pagesのビルドも.node-versionで24.19.0を指定します。

```powershell
npm ci
Copy-Item .env.example .env
```

`.env` の `GEMINI_API_KEY` に自分のGemini APIキーを設定してください。キーをチャットに貼る必要はありません。キーはローカルサーバーで扱い、ブラウザーには制限付きの一時トークンを渡します。必要なら同じファイルでモデルを変更できます。

```powershell
npm run dev
```

[アプリを開く](http://127.0.0.1:5173)。キーを変更した場合はサーバーを再起動してください。APIキー未設定でも録音、会議メモ、保存、検索、記録の読み込みを利用できます。音声対話・文字起こし・途中要約にはキーが必要です。

ビルドした版で使う場合：

```powershell
npm run build
npm start
```

## 使い方

1. 会議または動画を別のブラウザータブで開きます。
2. 「会議の記録を開始」でそのタブを選び、「タブの音声を共有」を有効にします。AIの音声出力が混ざる画面全体の音声共有は使用しません。
3. 文字起こしが会議記録へ届いたら、「音声で相談を始める」を押してマイクを許可します。「今の説明、どう思う？」等と話し、続けて相談できます。Alt + Shift + Cでも開始・終了できます。
4. 「相談を終了」で静かな同席状態に戻ります。会議記録は継続します。AIの回答中も利用者の音声を送り、サービスから割り込み通知が来ると再生中・待機中の応答音声を止めます。
5. 「記録を終了」で最後の音声区間を保存します。会議終了後も同じ会議を選んで相談を開始できます。

文字で相談する場合は、相談履歴の下の「テキストで相談」に質問を入力して「送信」を押します。Ctrl + Enterでも送信でき、Enterは改行です。マイクの許可や音声相談の開始は不要で、回答は相談履歴に表示されます。会議録音はその間も継続します。

音声とチャットは同じ相談履歴を参照・保存します。音声相談中にテキストを送ると音声相談を終了してチャットへ切り替わります。チャットの回答後に音声相談を再開すると、テキストでの相談も引き継ぎます。送信失敗時は相談文を履歴と入力欄に残し、再送できます。

## 映像を見る・費用を調整する

保存済みの画像は「映像の読取り記録」を開き、「画像を保存（ZIP）」で会議ごとにまとめて取り出せます。画像名は`企画会議_00-01-30-000.jpg`のように会議名と経過時間（時・分・秒・ミリ秒）を使います。同時刻の画像は連番で区別します。書き出しはブラウザー内で行い、追加のAPI利用はありません。画像本体のないJSON復元記録は除外し、保存済み画像だけを書き出します。

「映像も見る」をオンにすると、共有している会議タブを静止画として読み取ります。記録中でもオン・オフでき、音声記録は続きます。初期設定はオフです。

- 読取り間隔は15秒・30秒（標準）・60秒（節約）から選べます。APIの処理終了後に次の間隔を待つため、未処理の画像はたまりません。
- 「今の画面だけ読む」は映像オフでも一枚だけ読み取ります。資料が出た場面だけ確認する場合に利用できます。
- 画像は最大1280×720のJPEGに縮小します。成功した画像と時刻付きの読取り内容をローカルに保存し、「映像の読取り記録」で確認できます。
- 音声相談には時刻付きの読取り内容を渡します。映像オン時のテキスト相談には、保存した最新の静止画そのものも添付します。古い画像を現在の場面と混同しないよう時刻を渡します。
- オフにすると定期送信とチャットへの画像添付を止めます。送信済みの処理・読取り記録は残り、過去の読取り内容を文章として相談で参照できます。オフ後の場面は確認できません。
- APIが429（利用枠・頻度の上限）を返したら自動読取りをオフにします。上限を確認し、再びオンにするか単発で試してください。

映像オフ、間隔を長くする、必要な場面だけ単発で読むことで、新しい画像入力と読取り回答の処理量を減らせます。音声・テキストの処理、過去の読取りを含む文脈、オン時のチャットへの画像添付の費用は別に残ります。送信枚数は読取りAPIの呼び出し数で、請求金額ではありません。[Gemini公式料金](https://ai.google.dev/gemini-api/docs/pricing)と利用枠で確認してください。

連続動画の全場面・動きを理解する方式ではありません。静止画の間の出来事は見落とす場合があり、文字が小さい資料や細かな動きの評価は実機で必要です。映像の読取りはAIの解釈を含む別の記録で、音声の原発言・決定事項には自動転記しません。JSONバックアップには読取り文は含めますが画像そのものは含めません。

会議の観察には共有タブの音声だけを使い、マイクは相談中だけ利用します。ヘッドホンを使い、相談の音が会議側に戻らない音声設定で試してください。文字起こしや会議メモの追加は、AIへの回答要求として送信しません。

## 記録と文脈

- 会議音声は約10秒単位のWAVとしてブラウザーのIndexedDBへ保存してから文字起こしします。相談の切断は録音を止めません。文字起こしの失敗は該当区間に表示し、保存音声から再試行できます。
- 直近の文字起こし、時点付き途中要約、直近の相談履歴を対話開始時に渡します。対話中も新しい文字起こしを文脈へ追加します。
- 古い発言は `search_meeting` ツールで会議記録から検索します。初期版は語句の一致による検索です。画面からも検索できます。
- テキスト相談には直近の会議文脈と相談履歴に加え、質問の語句に一致した過去の発言を渡します。検索ツールによる追加取得は音声相談のみです。
- 会議記録と相談履歴は別の配列・入力元として保存します。相談での利用者の提案やAIの意見を会議の決定事項へ自動転記しません。
- 「会議メモ」は手入力の参照情報として明示します。途中要約はAIによる要約として表示します。

## 会議終了後の議事録と資料一覧

記録終了後、「議事録を作成・更新」で文字起こしを作文のような自然な日本語へ清書します。録音の区切りをつなぎ、時刻・区間番号・画像の補足を清書本文に入れません。要約ではなく、質問・回答・数値・条件・異論・未決事項をなるべく残します。長い会議は18000文字以内の文の区切りで分割し、直前の文脈も添えてGeminiへ順に送ります。各部分の成功を保存し、同じ記録で途中失敗した場合は未完了部分だけを処理します。旧形式の議事録は「作成・更新」で新しい清書へ変更できます。

議事録は「1. 清書」「2. 音声原本」「3. スクショ」の3部構成です。清書は読みやすい幅と段落間隔で表示します。音声原本は時間区間ごとに変換結果を空白・改行・記号も含めそのまま転記し、区間内に取得したスクショの時刻と参照を添えます。スクショは時刻順に並べ、AIの読取り内容は補足として開けます。手入力メモと相談履歴は清書・音声原本に混ぜません。

「議事録と画像を保存（ZIP）」にはHTML・Markdown議事録と、画像をまとめた「スクショ/」フォルダを含めます。ZIPを展開しHTMLを開くと、画像付きの議事録をそのまま読めます。未完了の音声を一括再試行してから議事録を作成すると欠落を減らせます。AI清書の確認用に原文を全て残します。JSON復元で画像本体がない場合も時刻と読取り文は残ります。清書にはAPI利用料金が発生しますが、音声原本・スクショ欄とZIPの組立てはブラウザー内で行います。

「記録を書き出す」は会議記録・相談履歴をJSONで保存します。録音音声は含まれません。「音声を保存」で会議音声を別途WAVで保存できます。JSONを読み込むと新しい会議IDで復元するため、既存の記録は上書きしません。ブラウザーのデータ削除で記録も消えるため、必要な記録は書き出してください。

## Google Driveへの自動保存

公開版でDriveを接続し、保存先フォルダと自動保存を設定すると、会議終了時に記録・相談履歴・音声原本・スクショ・作成済み議事録を会議ごとのZIPへまとめて保存します。終了後に文字起こしや清書が完成すると同じファイルを更新します。保存完了まではページを開いてください。初回の管理者設定と制約は[Google Drive設定手順](docs/GOOGLE_DRIVE.md)を参照してください。

## 検証

```powershell
npm test
npm run test:browser
npm run build
```

ブラウザーテストにはインストール済みChromeを使い、アプリをビルドして5174番ポートにテスト用サーバーを起動します。Edgeを使用する場合は `$env:BROWSER_CHANNEL = 'msedge'` として実行してください。合成音声とAPIの代替応答を使用し、実際の会議やGeminiに接続せずに記録継続と保存を確認します。スクリーンショットは `test-results/` に保存されます。

稼働中サーバーから実際のGemini接続だけを確認する場合は `node scripts/check-gemini.js --live` を実行します。合成した無音WAVと固定の試験文脈をGeminiへ送信し、API利用枠を消費します。保存会議は送信しません。文字起こし応答とLive接続成立の確認であり、実会話の品質試験ではありません。

実機の受け入れ試験は [docs/VOICE_ACCEPTANCE.md](docs/VOICE_ACCEPTANCE.md) を参照してください。自動テストの成功は、Geminiとの実音声対話やT1〜T9の合格を意味しません。

## 現在の制約

- 文字起こしが届くまで「今」の文脈には約10秒とAPI処理分の遅れがあります。発言が届いていない区間はAIへ未取得として渡します。10秒境界で単語が分かれる場合や、文字起こしの誤認識は実機で評価する必要があります。
- 映像は選択した共有タブの静止画を参照します。音声共有のないアプリ・端末は利用できません。資料ファイルの直接アップロードや連続動画保存は未実装です。
- 接続終了時の自動再接続は未実装です。相談履歴を保存し、ボタンで対話を再開します。短い対話を中心に検証してください。
- 録音の継続にはページを開いておく必要があります。終了操作前の直近の未保存音声は、ページの強制終了や端末のスリープで失われる可能性があります。長時間の録音、容量不足、音声の回り込みは実機検証が必要です。
- 公開版の会議・音声・画像もブラウザーに保存します。端末間の同期はありません。
